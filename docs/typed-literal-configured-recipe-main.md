# Typed planning, literal instructions and configured recipe information

The modern Minecraft source preserves a validated operator instruction of up to
2,000 characters through its initial request and both repair prompts. Typed goal
and action authority remains separate from those words. A late prohibition is
not shortened away to fit the planner.

Recipe questions can carry facts from an exact configured catalogue without
pretending those files were observed in the running game. That reply identifies
its configured snapshot and says that live load is unverified. It grants no
crafting or motor authority. A pending operator instruction or correction keeps
priority over a player recipe question. Model actions and plans are stripped
from an informational reply.

For a verified live recipe scope, the existing source lookup and private session
identity remain in use. If scope changes after an earlier identity was captured,
the configured reply cannot acquire that stale identity. The modern namespace,
secondary output, receiver, runtime and motor checks remain intact; 63 existing
methods were retained by an independent AST comparison.

## Terminal response for an instruction that cannot fit

The native compactor now raises a dedicated budget error only after safe
compaction cannot fit the original request. The controller carries this error
through to the runtime instead of converting it into another idle/replan
attempt. Full instruction text and late prohibitions remain intact; model text
cannot create the refusal's operator authority.

For the same current pending request, the runtime records `REFUSED` with:

> This instruction is too long for the current planner; try one task at a time.

This is a refusal, not task success or acknowledgement. It adds no skill,
actuator, plan adoption or learning-success credit. The existing operator API
returns all message statuses and the existing renderer displays both status and
response text, so no additional UI source change was required. That conclusion
comes from source inspection, not a live browser or endpoint test.

Original operator revision, literal request, model owner, instance, plan,
execution, deadline and suspension/input-release state are checked before
publication. A change after the write rolls the response back. Temporary writer
or intent-lock contention holds repeat model planning while the refusal awaits
durable storage. Known expired or replaced ownership retires before cooldown or
lock/database work. No deadline is extended.

A refused request cannot return as an active instruction after restart, and a
delayed delivery receipt cannot reopen it. This downgrade protection belongs to
`update_operator_message_status`; direct trusted `save_operator_message` remains
a separate intent-writing API. Fresh requests retain their ordinary priority.
The new enum value uses existing JSON storage without a schema migration or new
timestamp. Older readers cannot parse `REFUSED`: rollback needs a compatible
reader or fix-forward, and must not roll back the whole learning database.
