# Typed planning, literal instructions and configured recipe information

The modern Minecraft source preserves a validated operator instruction of up to
2,000 characters through its initial request and both repair prompts. Typed goal
and action authority remains separate from those words. A late prohibition is
not shortened away to fit the planner.

Recipe questions can carry facts from an exact configured catalogue without
pretending those files were observed in the running game. That reply identifies
its configured snapshot and says that live load is unverified. It grants no
crafting or motor authority. A pending operator instruction or correction keeps
priority over a player recipe question. Model actions and plans are stripped
from an informational reply.

For a verified live recipe scope, the existing source lookup and private session
identity remain in use. If scope changes after an earlier identity was captured,
the configured reply cannot acquire that stale identity. The modern namespace,
secondary output, receiver, runtime and motor checks remain intact; 63 existing
methods were retained by an independent AST comparison.

The [recorded proof](../evidence/public/typed_literal_configured_recipe_main_controls_20261001.json)
covers 76 distinct engineering cases across two attempts. It is not one clean
76-case passing run. The first attempt recorded 74 passes and two harness errors:
a fixture incorrectly expected a model request from the direct verified-recipe
path, and an audit hook misresolved a relative filename during private SQLite
fixture cleanup. Both negative results and their costs are retained. The second
attempt corrected those two setup issues, left all five production files
unchanged, and passed only the two affected cases. The other 74 were not rerun.

Both attempts used frozen source, real schema dependencies, fixture transport
and temporary SQLite. Each reauthenticated 500 files afterward and observed
all worker task masks on CPU 3. Numerical imports, model/tokenizer execution,
game inputs, network calls, live checkpoint writes and production controls were
forbidden. Workers were bounded to 45 seconds, 15 CPU seconds and 512 MiB address
space; their units allowed 512 MiB memory, zero swap, 55 seconds plus five seconds
for stopping. The complete outer containment was 67 seconds before termination
plus three seconds before final killing. Actual runs finished sooner.

Process high-water marks and the manager's retained pre-stop peaks use different
accounting. They are not summed or represented as a complete memory measurement.
Independent retirement checks confirmed exact PID/start disappearance and the
original owned cgroup path's absence. The helper did not record a cgroup inode,
so this is not an inode-authenticated cgroup identity claim.

These checks establish source correctness with fixtures. They do not establish
actual shared World generation, live deployment, engine-loaded pack bytes or a
selected client's binding to the current server session. The installed family
player still uses the earlier compatible source and its compactor successor.
Its successful connection does not establish useful planning, traversal or
Pokémon pack mastery.

The Native adapter still uses the existing unbound runtime path. A new bound
request deadline and operator-revision compare-and-swap guarantee are not
established here. A visible terminal response for an irreducible instruction is
also still open: the current runtime retries with capped backoff rather than
acknowledging that refusal. Actual typed model qualification remains required
before rollout; these checks make no quality, cost or throughput claim over dense.


## Permanent regression checks

Six focused repository regressions were separately checked against committed
main `221d384`. They retain the full 2,000-character literal and late prohibitions
through repair, configured quantities and scope notices, instruction priority,
the verified direct-source path, revocation without stale identity binding and
rejection of a model-supplied private marker.

All six passed with a mocked constrained model and fictional recipe/session
facts. Worker wall time was 2.677 seconds, CPU time 1.383 seconds and process
high-water mark 68,714,496 bytes; complete supervision took 3.332 seconds. The
[separate receipt](../evidence/public/literal_configured_recipe_regression_controls_20261001.json)
retains the bounds, source pins and independent physical retirement check.

These checks did not rerun or replace either earlier 76-case attempt. They made
no actual model, tokenizer, network, game or production-control calls. Their
result qualifies the regression code and mocked controller behavior, not live
planning, gameplay or pack mastery. The live-model and terminal-refusal gaps
listed above remain open.
