# Safety and Control Contract

This project must never assume that a software agent which controls keyboard/mouse input can also be trusted to stop itself.

## Non-negotiable invariants

1. The **supervisor** owns start, pause, resume, stop and motor capability leases.
2. Cognition cannot disable, mask, delete or reconfigure the stop path.
3. Loss of supervisor heartbeat immediately revokes motor capability.
4. Revocation always sends an unconditional release for every key/button the backend can hold.
5. The selected Minecraft instance is identified before control starts and revalidated continuously.
6. If per-instance scoping is lost, the motor backend fails closed.
7. Global desktop injection is never the default backend.
8. Live control is disabled until the backend's stop/focus-isolation tests pass.
9. A different X display is insufficient: autonomous Bedrock input requires a verified headless compositor and virtual-only seat. Host-fed nested sessions are held for observation, not automatically restarted when admission fails.

## Stop paths

At least two independent stop paths are required before release:

- CLI/control socket owned by the supervisor: `minecraft-ai stop`;
- an operator-owned mechanism outside the controlled Minecraft input path.

Examples of the second path may include a tray/menu control, a separate local web control bound to loopback with a random session token, a hardware/media key observed by the supervisor before the game, or a second-device control endpoint. Platform implementations must document which mechanism they use.

A keyboard shortcut delivered through the same in-game/global input channel is useful as a convenience but does **not** count as an independent emergency stop.

## State machine

```text
STOPPED
  -> STARTING
  -> SAFE_IDLE
  -> ARMED
  -> RUNNING
  -> PAUSED
  -> STOPPING
  -> STOPPED

any state --fault--> FAILSAFE --> STOPPED
```

Only the supervisor can transition `SAFE_IDLE -> ARMED -> RUNNING`.

## Capability lease

Motor output requires a short-lived capability lease containing:

- process/session id;
- target instance identity;
- backend identity;
- expiration/heartbeat deadline;
- allowed action set;
- maximum action duration;
- monotonically increasing sequence number.

The input backend rejects stale or replayed commands.

## Watchdogs

Fail safe on:

- stale frames;
- target window/process death;
- target identity mismatch;
- IPC disconnect;
- repeated deadline miss;
- malformed motor action;
- focus/scoping regression;
- supervisor heartbeat miss;
- explicit operator stop/pause.

## Testing gate

A platform/backend is not marked `live=true` until CI/manual hardware tests verify:

- stop while movement key is held;
- stop while mouse button is held;
- cognition crash;
- motor crash;
- capture crash;
- Minecraft crash;
- target-window replacement;
- operator changes focus;
- supervisor kill/restart;
- repeated malformed actions;
- stale frame stream;
- system suspend/resume;
- clean reboot recovery.

The expected result for every test is zero persistent held input and no control of a non-target application.

## Scoped input

### Java preferred path

A minimal client-side bridge receives only bounded input semantics and applies them to one client instance. It does not expose block coordinates, inventories, entities or other privileged game state when strict human-play mode is enabled.

### Compatibility paths

Where scoped injection is unavailable, use isolated desktop/session mechanisms before global input. Global injection requires explicit operator opt-in and a persistent warning.

## Data/model safety

- never execute code generated by a planner without a sandbox/allowlist;
- skills are typed data/policies, not arbitrary shell scripts;
- online wiki text is untrusted data and cannot directly become executable commands;
- model downloads are pinned by source and checksum where possible;
- third-party licenses are recorded before redistribution.
